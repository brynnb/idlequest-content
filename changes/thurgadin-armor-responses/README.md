# Thurgadin armor completion responses

All 14 class armor NPCs currently give the correct seven rewards for the correct armor component and three gems. This proposal restores their documented reward emote and addresses the player in the completion congratulation. It also restores Brita's documented "I see" hail, Mauren's "tasks for you to accomplish", and the complete plate helmet and greaves names in Dorinan's and Njall's instructions.

The baseline is unchanged. The proposal contains 14 complete `quests` row replacements and corresponding maintained Lua replacements. `recipes.json` records all 98 recipes, parsed independently from the cached P99 checklists and resolved against exported item names. NPC script keys and row IDs are in the proposal.

## Evidence and choices

Each class page is linked in the proposal with its retrieval timestamp and content hash. The cached pages consistently describe the NPC smiling warmly while handing over the reward. The original ProjectEQ Perl also includes that emote, which the generated Lua omitted. All 98 completion branches now call the supported NPC `Emote` API before speaking.

The P99 class overview blocks say "You have done well, _____." The proposal substitutes the player's clean name. Cleric slot-specific transcripts repeatedly say "You have done well." They conflict with that page's overview, so Dorinan retains the unnamed congratulation. The wiki's generic reward emote uses "he" for all 14 NPCs, including Brita; this proposal follows that transcript rather than inferring a pronoun from the original Perl or NPC appearance.

Punctuation and other uncertain transcript differences are retained. Recipe requirements, item rewards, 100,000 EXP and faction effects remain unchanged. The latter magnitudes are existing approximations, not exact P99 measurements. All recipes improve Coldain and Dain Frostreaver IV and worsen Kromzek and Kromrif, matching documented directions. This proposal does not establish exact reward magnitudes or complete P99 parity.

Quest faction prerequisites remain bypassed under IdleQuest policy. No class or level hand-in gate is added. The Cleric page explicitly says anyone of any level can complete the quest with faction, despite its minimum-level metadata. Brita's pie and napkin shawl hand-ins remain independent and unchanged.

These baseline scripts identify themselves as generated by `scripts/quests/velious-armor.mjs`. That compiler and its manifest are absent from this export workspace. Adoption in the game repository must reconcile these response changes with the generator before regeneration. The maintained copies and database rows in this proposal match exactly.

## Static acquisition audit

All 14 quest givers have exported placements through `npc_types.id -> spawnentry.npcID -> spawn2.spawngroupID`. None appears in the explicit NPC exclusion policy. All 46 distinct required materials have loot-table paths to placed NPCs in Velious zones. Armor components have Kael sources. This establishes static relationships only, not natural acquisition or final drop probabilities.

## Verification

Run from the repository root with Go on PATH.

```sh
python3 changes/thurgadin-armor-responses/verify-recipes.py
go -C validator test -run TestThurgadinArmor -v
THURGADIN_SCRIPT_DIR=../effective/quests/thurgadina go -C validator test -run TestThurgadinArmor -v
npm test
npm run validate
node tools/cli.mjs check-proposal . --proposal changes/thurgadin-armor-responses.json
```

The first test passes against the proposed scripts. The baseline command fails for each class because the completion emote is missing. The test executes all 98 proposed Lua recipes through the exported `items.lua` helper, with test doubles for player and NPC APIs. Each recipe is exercised twice, with missing gems, a substituted item, missing armor, armor alone and an unrelated item. It verifies rewards, consumption, returned coin, faction effects, EXP and completion responses. Separate assertions preserve both Brita kitchen alternatives and surplus-item returns.

This is Lua execution with a modeled hand-in boundary. It does not verify database settlement, rollback, rendered dialogue, inventory UI, world navigation or natural farming. The full IdleQuest checkout and Docker are unavailable here. Source syntax and immutable dataset validation are separate checks. MySQL rehearsal is not run.
